# 星辰御书房

一个以「御书房」为隐喻的个人学习自律 PWA：每日写下御案（任务 + 最低标准），入座专注点亮星辰，修炼心性获得御印，记录错题，晚间奏对复盘，最终在星图档案里看见长期的变化。

视觉方向为「昼夜双境」：白天是宣纸朱批的书房，入座专注时自动转入墨夜星空。

## 功能

| 页面 | 内容 |
| --- | --- |
| 今日 | 今日状态与下一步建议、御案（按天保存）、昨日未完成结转、今日奏对（五问复盘 + 御批） |
| 御书房 | 15/25/45/60 分钟专注，基于时间戳计时（切后台、刷新后可恢复），可绑定御案任务，分心记录与建议 |
| 修炼 | 五维心性修炼（沉稳/自律/洞察/格局/言行），完成后盖御印 |
| 错题阁 | 记录错题与错因，搜索、按错因/待重练筛选，首次重练点亮一颗星 |
| 档案 | 成长阶位与徽记、星图、人格五维雷达图、近 7 日专注、分心档案、奏对录 |
| 设置 | 主题（跟随系统/昼/夜）、入座即入夜、导出/导入备份、清空数据 |

规则说明：

- 只有完整完成一轮专注才点亮星辰；「提前收卷」只记录实际分钟数，不点亮星辰。
- 跨日归属：一轮专注（含提前收卷）的分钟与轮数记在**入座当天**，与绑定的御案同一天；即使跨过午夜或离开数日后才结算，也不会改记到结算日。
- 多个标签页同时打开时，数据会自动同步；每次保存前先读取其他标签页的最新写入，不会用过期副本覆盖。同一轮专注只会被结算一次：支持 Web Locks 时在锁内结算；不支持时由入座（或继续）的标签页结算，其他标签页在到点 5 秒后才代为结算。
- 未提交的输入（御案、奏对、错题表单）保存在当前标签页的 sessionStorage 中，刷新或版本更新后自动恢复。
- 快捷键：`1`–`5` 切换页面，`空格` 入座/暂停，`N` 新建御案，`/` 搜索错题，`T` 切换昼夜，`Esc` 关闭对话框。

## 数据

所有数据只保存在本机浏览器的 `localStorage`，没有后端、账号或同步。清除浏览器数据会丢失记录，请定期在「设置 → 导出备份」中保存 JSON。

| 键 | 用途 |
| --- | --- |
| `starryStudyRoom_v2` | 当前数据（`schemaVersion: 2`，任务和复盘按日期保存在 `tasksByDay` / `reviews`） |
| `starryStudyRoom_v1` | v1 的数据。v2 只在 `starryStudyRoom_v2` 不存在时读取一次用于迁移，**从不写入或删除** |
| `starryStudyRoom_v2_legacy_seen` | 迁移时 v1 键的指纹（长度 + 哈希），用于发现旧版页面后来的写入 |
| `starryStudyRoom_v2_corrupt_<时间戳>` | 无法解析的数据原文备份 |
| `starryStudyRoom_theme` | 首屏主题提示（防闪烁） |

- **新旧版本隔离**：v1 页面（未刷新的旧标签页、长期未关闭的旧版桌面应用）只会写 `starryStudyRoom_v1`，无法覆盖 v2 的按日历史。迁移后若旧版页面又改写了 v1 键，页面顶部会提示，可「下载原始数据」查看或用「导入备份」恢复；不会自动合并（旧版写入基于迁移前的数据，自动合并可能带回已删除的记录或重复计数）。回退到 v1 时，v1 仍能读到迁移前的数据。
- 迁移规则：旧任务列表归入当天，旧复盘按其更新时间归档。导入旧版备份文件同样会迁移。早期测试版本写在 v1 键里的 v2 数据会被完整接管。
- 若本地数据无法解析，原始内容会先备份再以空数据启动，不会直接丢弃。若连备份也写不进去（如存储已满），页面会停止保存并在顶部提示，用户可「下载原始数据」，并在确认后才放弃原数据。待迁移的 v1 数据无法解析时，v1 键保持原样，页面照常使用并提示可下载原文。
- 若本地数据来自更新的版本（`schemaVersion` 高于当前或无法识别），页面以只读方式打开。**只读保护期间**：浏览、切换页面不受影响；所有会写入数据的操作都会被拦截并提示「此操作未保存」，不会出现成功提示；外观调整只在本页生效；「导出备份」导出本机原文。
- 每次保存都要写入成功才算数：写入失败（如空间不足）时界面回滚到操作前并提示，不会显示未保存的结果。
- 导入只接受星辰御书房的备份（v1 / v2 导出包或原始数据），会校验版本与字段类型；只有写入本机存储成功才会提示导入成功，写入失败时当前数据保持不变。
- 已有的 `starryStudyRoom_v1_pre_v2_backup`（早期测试版本创建）保持原样，不再新建：v1 键本身就是完整的原文。

## 本地运行

无需构建，也没有依赖。

```bash
npm start        # python3 -m http.server 8080，然后打开 http://localhost:8080
npm run check    # 语法检查、Service Worker 预缓存与页面引用一致性、缓存名是否最新、id 引用与重复检查
npm run stamp    # 预缓存资源有改动后，重新生成 sw.js 的 CACHE_NAME
npm test         # node --test：数据迁移与损坏保护、导入校验、只读拦截、专注结算、Service Worker 升级等
npm run test:browser  # 真实无头 Chrome 端到端测试（见下）
```

需要 Node.js 18+（测试与检查脚本）和 Python 3（静态服务器，也可换成任意静态服务器）。

`npm run test:browser` 需要 Node.js 22+（内置 WebSocket）、本机安装的 Chrome / Chromium（可用 `CHROME_PATH` 指定）和 git（从 `main` 导出 v1 用于新旧版本共存测试）。无第三方依赖：通过 Chrome DevTools Protocol 驱动，覆盖损坏数据、未来版本只读、导入回滚、多标签页结算（含无 Web Locks）、v1 与 v2 同时运行、Service Worker 更新与草稿保护、离线、桌面 / 移动冒烟与性能。

## 结构

```
index.html          页面骨架、SVG 图标、对话框
css/
  tokens.css        设计令牌（昼/夜两套语义色、字号、间距、动效）
  base.css          重置、外壳布局、导航（手机底栏 / 桌面侧栏）
  components.css    按钮、表单、卡片、提示、对话框等通用组件
  pages.css         各页面专属样式
js/                 按顺序以普通 <script> 加载，共享全局作用域
  store.js          数据模型、迁移、持久化、渲染注册表（不操作 DOM）
  domain.js         纯业务规则与文案（统计、阶位、御批、修炼题库……）
  ui.js             图标、Toast、确认框、主题、路由
  today.js focus.js practice.js radar.js mistakes.js archive.js settings.js
  drafts.js         未提交输入的草稿保存与恢复
  app.js            启动、快捷键、跨日检测、多标签页同步、Service Worker 更新提示
sw.js               离线缓存（缓存优先，新版本提示刷新）
scripts/check.js    静态检查
tests/              node:test 单元测试
tests/browser/      无头 Chrome 端到端测试（harness.js 为无依赖的 CDP 工具）
docs/design-system.md  设计系统说明
```

修改 `index.html` 引用的资源时，需要同步更新 `sw.js` 中的 `FILES_TO_CACHE` 列表。`CACHE_NAME` 由「package 版本 + 预缓存资源内容哈希」组成：任何资源改动后都要运行 `npm run stamp`，否则 `npm run check` 会失败。新版本安装后会等待，用户点「刷新」后整组切换，不会新旧文件混用；只有点了「刷新」的标签页会重新载入，其他标签页只提示，不会被强制刷新。页面切回前台时和每小时会检查一次更新。
